# 1. アクセスログの1行を読む

## この章のゴール

ログ1行から、どのリクエストに何が起きたかを説明します。

## 1行が1リクエスト

この教材は JSON Lines 形式を使います。各行が独立した JSON オブジェクトです。ファイル全体を1個の JSON 配列として読む形式とは異なります。

```json
{"time":"2026-11-18T00:00:00Z","method":"GET","path":"/items","status":200,"request_time_ms":120,"request_id":"req-001"}
```

| 項目 | 意味 | 読むときの注意 |
|---|---|---|
| `time` | この教材では応答完了時刻 | `Z` は UTC。日本時間では09:00:00 |
| `method` | HTTP メソッド | GET、POST など |
| `path` | リクエストのパス | この教材ではクエリー文字列を記録しない |
| `status` | 記録地点が返した HTTP ステータス | 200でも内容が正しいとは限らない |
| `request_time_ms` | 記録地点で測った処理時間 | 単位はミリ秒。1000 ms が1秒 |
| `request_id` | リクエストを調べるための ID | 対応するアプリログと照合する手がかり |

実際の Nginx や Apache のログは、設定によって項目と形式が変わります。Nginx の `$request_time` は秒単位です。この教材の `request_time_ms` と混ぜて比較しないでください。

## ステータスを分類する

| 範囲 | 大まかな意味 | 例 |
|---|---|---|
| 2xx | リクエストを正常に処理した | 200 |
| 3xx | 転送など | 301、304 |
| 4xx | クライアントの要求などに関するエラー | 404、429 |
| 5xx | サーバー側の処理で起きたエラー | 500、502、503 |

404 は存在しない URL、429 は要求の制限などで返ります。4xx をすべて利用者の操作ミスと決めつけてはいけません。公開直後に404が増えた場合は、壊れたリンクや配信設定も調べます。

## どこで記録したログか

CDN → リバースプロキシ → アプリという経路なら、それぞれで記録できる範囲が違います。プロキシの502と、アプリの500は同じ意味ではありません。キャッシュで返った応答は、アプリのログに残らないこともあります。

本教材のログは、Web サービスの入口で応答を完了したリクエストを記録した想定です。アクセスログだけでは、DNS 障害や応答未完了のリクエストを把握できません。処理時間も、利用者のブラウザーでの表示完了時間とは異なります。

確認: `00:01:10Z` は日本時間で何時でしょうか。答えは **09:01:10** です。障害の報告時刻とログのタイムゾーンを最初にそろえます。
