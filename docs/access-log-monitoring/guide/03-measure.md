# 3. 件数と割合を比べる

## この章のゴール

同じ長さの時間窓で、正常・異常・復旧を比べます。

## 集計してみる

付属スクリプトは、終了時刻の直前1分を集計します。全パスを対象にし、5xx をエラー、1000 ms 以上を遅いリクエストとします。

```powershell
$ends = @('2026-11-18T00:01:00Z', '2026-11-18T00:02:00Z', '2026-11-18T00:03:00Z')
$results = @($ends | ForEach-Object {
    .\Measure-AccessLog.ps1 -Path .\access.jsonl -End $_
})
$results | Format-Table End, Requests, ServerErrors, ErrorRatePercent, SlowRequests, P95Ms, State
```

| 時間窓（UTC） | 件数 | 5xx | 5xx 率 | 1000 ms 以上 | p95 | 状態 |
|---|---|---|---|---|---|---|
| 00:00以上、00:01未満 | 10 | 0 | 0% | 0 | 180 ms | OK |
| 00:01以上、00:02未満 | 10 | 3 | 30% | 4 | 1800 ms | ALERT |
| 00:02以上、00:03未満 | 10 | 0 | 0% | 0 | 220 ms | OK |

## 母数を一緒に見る

5xx 率は `5xx 件数 ÷ 全リクエスト数 × 100` です。4xx は母数に入りますが、この式の分子には入りません。1件中1件の失敗も、1000件中1000件の失敗も100%です。割合だけで影響の大きさを判断しないでください。

集計対象も明示します。実運用では `/health` への機械的なチェックが大量にあると、利用者の API のエラー率が薄まります。全体と主要な操作ごとの集計を分けるか、除外するパスと理由を決めます。本教材では30件のすべてを対象にします。

## p95 を読む

p95 は、処理時間を昇順に並べたとき、約95%のリクエストが収まる値です。このスクリプトは **`切り上げ(0.95 × 件数)` 番目**の値を採用します。10件の場合は10番目なので最大値と一致します。平均値だけでは見えにくい遅さを探せますが、この小さな標本で安定した傾向まで分かるわけではありません。

集計ツールによって補間や近似の方法が異なります。同じ p95 という名前でも計算方法を確認します。本教材の警報条件には p95 を使わず、遅いリクエストの件数を使います。

## 記録する

「09:01台の入口のアクセスログでは10件中3件が5xx、4件が1秒以上。09:02台の次の10件では、どちらも0件だった」と書いてみましょう。対象、時刻、母数、結果をそろえると、他の人と調査を引き継ぎやすくなります。
