# 講師用ガイド

## 開催前の確認

受講者と同じ PowerShell の版、実行ポリシー、ブラウザーの保存方法で、準備から後片付けまで試してください。実行制限がある PC では、第2章の対話的な集計と第3章の結果表を使って説明できます。

リポジトリでは `npm run test:access-log` が配布スクリプトの動作を検査します。PowerShell のある環境が必要です。Windows PowerShell 5.1 を検査する場合は `powershell -NoProfile -File scripts/test-access-log.ps1` を使います。

## 進行例

75分の場合、準備10分、読み方10分、絞り込み15分、集計15分、監視条件15分、振り返り10分を目安にします。時間が短ければ p95 の詳しい計算法は後から読みます。

第2章では「5xx だけで、利用者の困りごとを全部拾えるか」を問いかけ、200の遅い行を探してもらいます。第4章では復旧データの後に `NO_DATA` が続く例を示し、観測できない状態を復旧にしないことを確認します。

## 振り返りの答えの例

1. 母数、時間窓、対象の操作が必要。3件中3件と100万件中3件では読み方が異なる
2. 処理時間を見る。教材では `request_time_ms >= 1000` を使った
3. アクセスがない場合と、入口や収集の障害を区別できないため
4. 出さない。十分な母数での正常を確認する。重要な低頻度の操作には別の監視を設ける
5. 同じ時刻やリクエスト ID のアプリログ、プロキシのエラーログ、依存先の観測を確認する

## 発展課題

- 5xx 率の条件を40%にしても、異常窓が遅さの条件で `ALERT` になる理由を説明する
- 正常窓に404があっても、この監視では `OK` になる理由を説明する
- 自分のサービスで重要な操作を1つ選び、パス、許容する遅さ、母数、通知先、最初の調査先を書く

この演習で収集器の運用、自動通知、本番の負荷に耐える集計まで検証したとは扱いません。
