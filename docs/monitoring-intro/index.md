# インフラ監視実践入門

「ネットワーク、サーバー、DB、アプリ。分類から読むと、結局何をすればよいのか分からない」。この教材では、**URL が返事をするかを確かめるだけ**のところから始めます。

困りごとが見つかったら、観測を1つだけ足します。「全部を集める」前に、何を確かめたいかを決めましょう。

## この教材のゴール

- 小さな Web アプリを止めて、異常を検知し、復旧を確かめる
- 「HTTP 200」と「利用者が必要な操作をできる」を区別する
- 応答時間・通知の頻度・監視自身の停止を扱う
- 異常の検知と原因の調査を分け、必要な証拠から調べる
- その監視で分かることと、まだ分からないことを説明する

Spring や業務アプリの実装知識は不要です。Python のコードを最初から書く必要もありません。配布された小さな実験用アプリと監視スクリプトを動かし、短いコードを読む順番で進めます。Prometheus や Grafana の導入は前提にしません。

## 実験するもの

同じ Ubuntu 上で、Web アプリ、SQLite の学習用データ、監視スクリプトを動かします。Python 3 の標準ライブラリーだけを使い、pip での追加インストールはしません。

SQLite はファイル型の DB です。PostgreSQL のような別プロセスの DB サーバーではありません。本教材の「DB を使えなくする」は、**学習用 DB ファイルを一時的に退避する実験**です。実サービスの DB 停止やネットワーク障害を再現したとは言いません。

## 進め方

| 章 | 最初に感じる困りごと | 足すもの | 目安 |
|---|---|---|---:|
| [準備](./guide/00-prepare.md) | 安全に壊して戻せる場所がない | 専用のローカル実験環境 | 事前準備 |
| [1. URL を確かめる](./guide/01-url.md) | アプリが止まったか分からない | 手動の HTTP 確認 | 15分 |
| [2. 繰り返して確かめる](./guide/02-periodic.md) | 人が見続けられない | 間隔・時刻・タイムアウト | 15分 |
| [3. 必要な操作を確かめる](./guide/03-operation.md) | 200 なのに使えない | 既知データの読み取り確認 | 20分 |
| [4. 遅さを確かめる](./guide/04-latency.md) | 成功するが待たされる | 応答時間の条件 | 15分 |
| [5. 通知を整える](./guide/05-alerts.md) | 毎回鳴って大事な通知を見落とす | 連続失敗・重複抑制・復旧通知 | 20分 |
| [6. 原因を絞る](./guide/06-diagnose.md) | 異常は分かったが理由が不明 | ログと必要な追加確認 | 20分 |
| [7. 監視自身を確かめる](./guide/07-watchdog.md) | 監視が止まっても静か | 最終観測時刻の別チェック | 15分 |
| [整理と後片付け](./guide/08-review.md) | 学んだことを別の環境に応用したい | 後から名前と限界を整理 | 15分 |

準備を除いて約 2〜3 時間です。前半だけを 60〜90 分で実施し、後半を次回に分けても構いません。

各章は「困りごと → 小さな追加 → 安全な故障 → 復旧 → 確かめた範囲」で進みます。成功画面を見るだけで終わらず、**失敗を検知した記録と、復旧した記録を一つずつ残す**のが到達点です。
